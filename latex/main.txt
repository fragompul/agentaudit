AgentAudit: How Much of an Agent Leaderboard Is Signal?

Francisco Javier Gómez Pulido

                                                     Abstract

          Agent leaderboards report one number per system, usually from one run per task. We
           ask how much of that number is signal, and how much of the usual statistical machinery
           survives when every task is run several times. We present AgentAudit, a typed and
           tested library (unbiased pass@k and passk, task-level intervals, variance decomposition,
           paired tests with multiplicity control, ranking uncertainty, power planning, anytime-valid
           sequential comparison) and AgentAudit-Bench, an offline, deterministic, state-verified
           suite of 360 generated tool-use tasks. In simulations against known truth, pooling all runs
           gives 95% intervals that cover only 68.3% of the time with ten runs per task, and run-level
           tests that reject a true null in 17.9% of simulations; task-level procedures stay close to
           nominal, although the task bootstrap is optimistic with 20 tasks and extreme prevalence
          (down to 81%). Whether tasks or repeats are better at a fixed budget depends on the
           agent-by-task interaction: they are equivalent when it is small and tasks are better when it is
           large. Re-analysing 129 public SWE-bench Verified submissions, 28.3% of agent pairs are not
           distinguishable after Holm correction, and adjacent leaderboard positions are almost never
           separated (0/128 overall, 3/40 among entries that declare a single attempt); full coverage
           of the 500 instances could be verified for only 110 entries, and the share of separable pairs
           changes by less than two points under alternative treatments of missing logs. On tau-bench
           the gap between two frontier models is detected in retail for the mean-score estimand (not
          when runs are reduced to per-task majority outcomes) and not detected in airline, which
           is not evidence of equality. On 7 local models (10 runs on 120 tasks) run-to-run noise
           accounts for 34% of the variance of single-run outcomes, and a plug-in estimate says a 5-point
           difference would need about 387 tasks (a limited case study: only aggregates are stored and
           the run was not repeated).

1 Introduction

Public leaderboards for LLM agents, from SWE-bench (Jimenez et al., 2024) to  -bench (Yao et al., 2024) and
the Holistic Agent Leaderboard (Kapoor et al., 2026), rank systems by a single success rate, often obtained
from one run per task. Claims of a "new state of the art" are made on differences of one or two points.
Three sources of randomness are rarely separated: which tasks were sampled, which run of a stochastic agent
was recorded, and how the agent and the task interact. The principle that evaluations need error bars is
established (Miller, 2024; Bowyer et al., 2025; Madaan et al., 2024; Bouthillier et al., 2021). What is less
settled for agents is (i) which task-level procedures stay valid when every task is run several times, (ii) how
a fixed budget should be split between more tasks and more repeats, and (iii) how much of an existing
leaderboard survives a statistically careful reading.

Terminology. A task is one problem instance; a run is one attempt of one agent on one task (for SWE-bench
entries we keep the leaderboard's own field name attempts, the number of runs per task a submission used to
produce each answer); R is the number of runs per task and T the number of tasks. The benchmark score of
an agent is the mean over tasks of the per-task success rate. pass@k is the probability that at least one of k
runs of a task succeeds, passk the probability that all k succeed; both are averaged over tasks.

Research questions.

                                                                      1
RQ1 When runs are clustered within tasks, which interval and test procedures keep their nominal coverage
           and error rate, and how badly do procedures that pool runs fail?

RQ2 At a fixed budget of runs, is it better to spend it on more tasks or on more repeats, and what does the
           answer depend on?

RQ3 How many differences between agents on public leaderboards (SWE-bench Verified,  -bench) are
           statistically distinguishable, and how sensitive is that count to what the public data do and do not
           document?

RQ4 Does anytime-valid sequential comparison control false positives under continuous monitoring, and
          what does it cost in power?

RQ5 On a controlled benchmark with several runs per task, how large is run noise relative to the score, and
           how reliable is the ranking of the evaluated agents?

Our working hypothesis was that many leaderboard differences are not distinguishable and that pass@k hides
unreliability that passk reveals. We report where the evidence supports it and where it does not.

Findings in brief. (1) Pooling runs is not merely loose: with ten runs per task, a nominal 95% pooled
Wilson interval covers 68.3% (68%­76% when tasks are very heterogeneous), while task-level intervals stay
within 91.6%­95.5% (task bootstrap) and 93.2%­95.9% (beta-binomial) for T  50; with T = 20 and one run
per task at extreme prevalence the task bootstrap falls to 81%­82%. (2) Run-level tests reject a true null in
17.9% of simulations when the interaction is large; the task-level sign-flip test stays at or below nominal, and
the bootstrap and t tests are within about two points of it even for skewed differences. (3) At a fixed budget,
tasks beat repeats only when agent-by-task interaction is non-negligible: the standard-error ratio of ten runs
versus one is 0.96­1.04 for small and 1.54­1.56 for large interaction. (4) On SWE-bench Verified, 28.3% of
pairs are not separable; adjacent positions are almost never separable, but the exact count depends on which
entries are kept (Table 1). (5) A confidence sequence controls false positives under peeking (1.3% against
36.5% for naive peeking) at a price in power. (6) On local models, run noise is 34% of variance, the best
model's pass10 is 40.8% against a one-run score of 63.7%. 2 of the 7 models are near the floor (below 10%),
where differences are trivially separable but uninformative about agent quality.

2 Related Work

Statistics for LLM evaluation. Miller (2024) gives standard errors, clustered errors, paired differences
and power formulae for single-run question-answering evaluations; Bowyer et al. (2025) show that central-limit
intervals fail for small benchmarks and recommend Bayesian or exact alternatives; Madaan et al. (2024)

                                                                      2
quantify seed variance in training and evaluation; Biderman et al. (2024) document reproducibility pitfalls.
Earlier work in NLP and RL made the case for significance testing, power and robust aggregation (Dietterich,
1998; Dror et al., 2018; Card et al., 2020; Agarwal et al., 2021; Bouthillier et al., 2021). The clustering
argument itself is classical survey methodology (Kish, 1965). We build on this literature but target agents:
several runs per task, outcomes verified by state, and the question of how to spend a budget.

Agent evaluation and reliability.  -bench introduced passk to measure consistency across trials (Yao
et al., 2024); Kapoor et al. (2024) argued that agent benchmarks must account for cost and reproducibility;
HAL standardised large-scale agent evaluation (Kapoor et al., 2026). Huang (2026) propose an estimand-aware
pairwise procedure for agent leaderboards and report unresolved close rank differences on SWE-bench and
 2-bench; Neuhof & Benjamini (2026) build rank intervals for MMLU from pairwise tests. Our contributions
are complementary: a crossed variance decomposition over agents, tasks and runs, a closed-form allocation
rule, validation against synthetic ground truth with robustness checks, an offline benchmark with controlled
stochasticity, and an all-pairs re-analysis whose sensitivity to undocumented evaluation details is reported.

Paired tests and multiplicity. Sign-flip (randomisation) tests are exact under a symmetry assumption,
which is stronger than a zero mean; their behaviour for the weaker null is studied by Romano (1990) and the
studentised version by Janssen (1997). We use Holm adjustment (Holm, 1979), which controls the family-wise
error under arbitrary dependence, and Benjamini­Hochberg (Benjamini & Hochberg, 1995), whose guarantee
needs independence or positive dependence (Benjamini & Yekutieli, 2001); pairwise tests that share agents
are not independent.

Anytime-valid inference. Confidence sequences (Howard et al., 2021) and betting-based constructions
for bounded means (Waudby-Smith & Ramdas, 2024; Ramdas et al., 2023) permit continuous monitoring.
Recent work applies them to LLM evaluation and online ranking (Hsu & Shekhar, 2026; Gu et al., 2026).
The confidence sequence we use is the predictable plug-in, hedged betting construction of Waudby-Smith &
Ramdas (2024) applied unchanged to paired per-task differences, so the construction is not a contribution of
this paper; what we add is the explicit equivalence stopping rule and its error statement, an implementation
audit (nonnegativity, predictability, grid), and a simulation of what it costs and buys relative to fixed-sample
tests and to naive peeking. Hsu & Shekhar (2026) (sequential evaluation of a new model on a fixed question
set, choosing which questions to query) and Gu et al. (2026) (online ranking from pairwise comparisons) use
related e-process machinery for different designs; we do not compare against them empirically. Equivalence
claims require a pre-declared margin (Lakens, 2017).

3 Preliminaries and Methodology

Setting and estimand. Agents m = 1, . . . , M are evaluated on tasks t = 1, . . . , T with R runs each, giving
scores Ymtr  [0, 1] (binary in our benchmark). We regard tasks as an i.i.d. sample from a task population
and runs as conditionally independent given agent and task. The estimand of an agent is the population
benchmark score µm = Et[pmt], where pmt = E[Ymtr | m, t]. Agents are treated as fixed: the M evaluated
systems are not a sample from a population of agents, so the agent component below describes the spread of
these M systems rather than a population variance. Section 8 states what this does and does not license.

The plain sign-flip test is exact (conditionally on |dt|) only under the strong null that each dt is symmetric

about zero, which holds if the two agents are exchangeable within each task; it is not exact for the weak

null E[d] = 0 with skewed d (Romano, 1990), for which the studentised version is asymptotically valid by

analogy with the studentised permutation theory of Janssen (1997), who treats the two-sample problem;

we did not prove the one-sample result and check it by simulation (E1). It is enumerated exactly up to

14 non-zero differences; beyond that it is Monte Carlo with nperm = 20,000 seeded draws and p-value
(1 + #{|S|  |S|})/(nperm + 1). McNemar's test needs one binary outcome per task: for R = 1 it is exact

and conditional on the discordant pairs; for R > 1 we use the per-task majority outcome (strictly more than

half of the runs; a task with exactly half is scored as a failure, an arbitrary convention). This changes the

estimand to the difference of majority-success rates and discards the run-level information; it is a sensitivity

analysis, not a conservative version of the primary test (Appendix F shows cases where it is less and more

significant than the mean-score analysis, depending on how ties are treated). Pairwise p-values are adjusted
by Holm (Holm, 1979) (family-wise error under any dependence) or Benjamini­Hochberg (Benjamini &
Hochberg, 1995) (false discovery rate under independence or positive dependence (Benjamini & Yekutieli,

What a non-significant difference means. Failing to reject H0 : µa = µb means a difference was not
detected at this sample size. It is not evidence of equality. Equivalence is claimed only when a confidence
interval or sequence lies inside a pre-declared margin (Lakens, 2017); "not distinguishable" in this paper
never means "equivalent".

3.5 Ranking uncertainty

We resample tasks (the same tasks for every agent), recompute scores and ranks (ties broken uniformly at
random) and report rank distributions, P (best), the matrix of P (Y¯i > Y¯j) and the fraction of pairs that
cannot be told apart. A split-half Kendall  measures whether a fresh task sample would reproduce the
ordering. Wide rank intervals show ranking uncertainty; they do not show that agents are equivalent.

B = T R this equals (Rst + se)/B, which is increasing in R whenever st > 0: if tasks are free, a fixed number
of runs is best spent on more tasks, and the advantage grows with the interaction m2 t (it vanishes as st  0).

4 AgentAudit-Bench

Environments. Six simulated worlds, all offline and deterministic: a virtual file system; an in-memory
SQLite database; a REST-style CRM (customers and tickets); room bookings; web forms with validation and
option codes; and a tabular data world with a restricted calculator. Each exposes 4­7 tools; tool errors are
returned as observations, so an agent can recover from them.

Tasks. A procedural generator creates 360 tasks (60 per family) from a seed. Each family has five templates
(for example, "move every .txt file into /archive", "upgrade every customer in a city"), and two knobs
sweep a factorial grid: horizon (1­4 required operations or, for forms, 1­3 forms) and distractors (0­2:
confusable files, decoy tables, same-surname customers, extra forms, extra rows). Free-text values are quoted
in instructions to avoid punctuation ambiguity, a flaw found when auditing early traces. A balanced one-third
core subset (120 tasks, 20 per family) is used for the local-model evaluation.

Verification. Success is decided by the final world state or the submitted answer, never by the agent's text.
Every task is audited automatically in the test suite: a reference oracle must solve it, a do-nothing agent
must not, and generation and resulting state must be deterministic in the seed. These checks establish that
tasks are solvable and non-trivial, not that the checker accepts every valid alternative solution: only the state
the generator anticipates is verified.

Controlled stochasticity. The benchmark includes a fault injector that fails each tool call independently
with probability q, drawn sequentially along the call sequence from a generator seeded by (task, run) and
independent of the agent; a failed call leaves the world unchanged and returns a transient 503, and injections
are logged. Because draws are indexed by call number, two agents face the same failure pattern only if they
make calls in the same order, so the injector gives matched failure probability and seeds, not identical failure
events. The injector is implemented and tested but was not enabled in the experiments reported here.

Agents and reproducibility. Agents implement a small interface. All local models use one uniform
text tool protocol: tools are listed as JSON in the system prompt, a call is any JSON object with name
and arguments, one call per turn is executed, and generation stops after it. Using one protocol removes
chat-template differences from the comparison; it also sidesteps a server-side tool-call defect we observed once
(Appendix B). A record/replay cache keyed by agent configuration, message history, tools and seed makes an
experiment replayable without the model, provided the cache is available; the cache and the raw trajectories
of the local-model run are not in the repository, so the local-model numbers can be recomputed from the

                                                                      6
stored aggregates but not from raw runs. The runner executes runs in run-major order, so any prefix of an
interrupted evaluation is balanced, and resumes from checkpoints.

5 Experimental Protocol

All simulation experiments were specified before they were run (docs/experiments.md: question, design,
result that would support the claim, result that would contradict it); unfavourable outcomes are reported below.
Every random stream is seeded, the scripts are in scripts/, and every number in this paper is produced from
the stored aggregates in results/ by scripts/make_paper_assets.py; whether the aggregates themselves
can be recomputed from raw outcomes differs by experiment (Appendix G).

Simulated agents. Synthetic agents follow a logit-normal item-response model, pmt = (m - bt + gmt)
with bt  N (0, b2) and agent-by-task interaction gmt  N (0, g2), and Ymtr  Bernoulli(pmt) independently
across runs. Population scores, passk and differences are computed by Gauss­Hermite quadrature, so coverage,
error rates and power are measured against exact truth. The model is a convenient generator, not a claim
about real agents; the robustness experiments vary its parameters.

Experiments. S0 (RQ1, RQ2, RQ4, ranking calibration): the original coverage, type-I error, fixed-budget
design, sequential and ranking simulations, 2000 replications per coverage cell. E1 (RQ1): type-I error of the
paired tests when dt is skewed with mean zero (weak null), T  {20, 50, 100, 300}, R  {1, 5}, 1500 replications.
E2 (RQ2): tasks versus repeats over task heterogeneity × interaction, 1500 replications. E3 (RQ1): coverage
across prevalence, heterogeneity, T and R, 1000 replications. E5 (RQ4): sequential stopping with margins
{0, 0.03, 0.06, 0.10} and minimum task counts, 2000 replications. E6 (RQ3): pairwise distinguishability
and Holm family-wise error on a six-agent leaderboard with an exactly tied pair, 400 replications. (The
fixed-budget comparison was not repeated on the local-model data; see Section 6.4. S0 designates the
simulations of the first version of this study; four of its five components (coverage, type-I error, fixed-budget
design and ranking calibration) were re-run unchanged in the final audit and every stored numeric value was
reproduced bit for bit, wall-clock times excepted (command and log in FINAL_REPRODUCIBILITY_REPORT.md).
The fifth, the sequential comparison (S4), was not part of that comparison: it was regenerated after the
confidence-sequence grid correction and its values differ from the first version's; the current script reproduces
the current stored file bit for bit in a separate re-run. An earlier re-run during the first revision is supported
only by commit history, not by a log.) Monte Carlo standard errors are about 0.6 points for a rejection rate
near 5% with 1500 replications and 0.7 points for a coverage near 95% with 1000.

SWE-bench Verified (RQ3). Per-instance resolved lists of every submission in the public
swe-bench/experiments repository that declares at least 50 resolved instances, 129 entries on 500 in-

them: an entry's coverage is verified when the union of its public log folders and its no_generation instances

distinguish a documented failure (no_generation: the system produced no patch), an absent evaluation log
(no_logs: the outcome is unobserved, and the official score counts it as unresolved), and a verified complete
coverage record (folders plus no_generation account for all 500 instances and no_logs is empty). The
headline analysis keeps the official convention for all entries; sensitivity analyses keep coverage-verified entries,
single-attempt entries, and both.

6 Results

6.1 Simulation: validating the statistics (RQ1, RQ2, RQ4)

Interval coverage (RQ1). Figure 1 shows coverage of nominal 95% intervals for the benchmark score
(b = 1.5, interaction sd 0.5). With one run per task the pooled binomial intervals are fine (they are exact
in that case). With three runs they cover 88.5% of the time and with ten runs only 68.3% (100 tasks;
Monte Carlo s.e. 1.0 points), as the design effect predicts. A runs-only bootstrap is worse (56.4%). The task
bootstrap, its BCa variant and the hierarchical beta-binomial interval stay close to nominal (task bootstrap:
94.8% at ten runs; BCa 94.8%; beta-binomial 95.1%), and the two-stage bootstrap is conservative (96.4%).
Coverage of the task bootstrap for passk ranges between 90.8% and 94.8%. Full numbers are in Appendix D.

Robustness of coverage (E3). The ranking of methods holds across prevalence and task heterogeneity,
but the task bootstrap is not uniformly near nominal (Figure 2). For T  50 and R > 1 it covers 91.6%­95.5%
and the beta-binomial interval 93.2%­95.9%. With T = 20, one run per task and extreme prevalence with
homogeneous tasks the percentile bootstrap covers only 81%­82% (BCa: from 80%) because the resampled
score is nearly degenerate; the pooled Wilson interval is valid there and should be preferred. The runs-only
bootstrap has zero coverage at R = 1 (0%) because it sees no variation. The pooled Wilson interval fails only
when runs are clustered and tasks differ: at ten runs and task sd 1.5 it covers 68%­76%, and it is roughly
nominal when tasks are nearly homogeneous. The grid is small (T  {20, 50, 100}, R  {1, 3, 10}, three
prevalences, two levels of task heterogeneity, 1000 replications per cell, Monte Carlo s.e. up to 1.6 points), so
we do not derive a sample-size threshold from it. What it supports is conditional: where runs are clustered
within tasks the pooled interval should not be used, task-level intervals are the better default but are mildly
optimistic even at T  50 (coverage as low as 91.6%), and for very small single-run evaluations an exact
binomial interval is preferable.

hardly matters, because the task main effect cancels in a paired difference. The cost-optimal number of runs
per task for a task that costs ten runs is 32 with small interaction and 7 with large interaction. If the pool of
tasks is capped (for example at 120), the question changes and the extra budget must go to repeats. Analytic
and simulated standard errors agree to within 4.6% in E2. Repeats are not useless: they identify run noise
and enable passk.

6.3 Local open-weight models (RQ5)

Setup and headline numbers. 7 models, 120 tasks, 10 runs each (8 400 runs in total). Success rates
range from 0.0% (qwen2.5-3b-q2) to 63.7% (qwen2.5-7b); the full table with passk and per-family scores is in
Appendix E. Figure 11 (left) shows 95% task-bootstrap intervals. Scores here combine two things: protocol
validity (does the model emit a parseable action in the uniform text protocol?) and task competence. The
quantised variant qwen2.5-3b-q2 never produced a parseable action (100% of its runs end with no tool call),
so its score of zero measures protocol failure and says nothing about the underlying agent; we keep it as a
degenerate control rather than dropping it silently, and it contributes to the variance decomposition and the
pair counts as a floor. Without it, 1 of the 15 remaining pairs are not separable after Holm (recomputed
from the stored pairwise p-values); the variance decomposition and the rankings without it could not be
recomputed because the per-run outcomes are not stored (Appendix G). Backend errors (49 runs, 0.6%) are
scored as failures. Results are specific to this protocol and these quantised models.

Reliability is much lower than the headline score. The best model's score of 63.7% falls to 52.9%
for pass3 and 40.8% for pass10: a model that solves a task on average does not solve it every time. Run
noise accounts for 34% of the variance of single runs, task difficulty for 14%, agent-by-task interaction for
26% and agent identity for 25%. The agent share describes the spread of these seven fixed models, not a
population variance. Run noise is of the same order as the quantity of interest, so a one-run evaluation is a
noisy measurement even here.

Ranking: the hypothesis is only partly borne out. Because the models differ a lot in capability,
the ranking is well determined: 1 of 21 pairs are not separable after Holm correction (llama3.2-3b versus
qwen2.5-3b, a gap of 1.7 points, adjusted p = 0.67), and the split-half rank correlation is 0.94. This contrasts
with SWE-bench, where scores are close; the statistical problems are most severe when systems are close,
not absent otherwise. A plug-in power calculation says that resolving a 5-point difference between two of
these agents at 80% power needs about 387 tasks at ten runs per task, more than three times the suite size,
and the minimum detectable difference of the current design is 9.0 points; both are estimates from one pilot
and carry the uncertainty documented for  -bench above. With the cost model of Section 3.6, the optimal
number of runs per task is 4 when a task costs as much as ten runs.

6.4 Ablations on real data

Tasks versus runs. The sub-designs are random subsets of the same 120 tasks and ten runs, compared
with the ranking and the significant pairs of the full data. The full-data ranking shares observations with
every subsample and is itself an estimate, so this measures internal stability relative to the full observed
sample, not recovery of an independently known population ranking; the pairs that are significant in the full
data are also selected by the same data, so sign agreement among them is optimistic. Recovery of a known
ranking is examined in the simulation (E6, Figure 8); a split-sample analysis on independent halves would
require the per-run outcomes, which are not stored. Sub-sampling the real data (Figure 12), a ranking from
all 120 tasks with one run per task has Kendall  = 0.98 with the full-data ranking and separates 85% of the
pairs, against 95% with ten runs. With only 12 tasks and one run the ranking correlation is  = 0.86 and
only 12% of pairs are separated. Since the large gaps are easy, rank correlation saturates quickly; the number
of separated pairs is the informative measure and it keeps growing with both tasks and runs. We did not
repeat the fixed-budget comparison of Section 6.1 on real data, so the simulation result on tasks versus runs
is neither confirmed nor refuted here.

Sequential stopping. Applying the confidence sequence to tasks in random order, 93% of the 20 pairs
that are significant on the full data are decided before the tasks run out, with a median of 29 tasks. This
re-orders existing results; it is not a live stopping experiment. Large gaps are settled after a few tens of tasks;
close pairs are not decided within the suite, as in the simulation.

Cost profile. Figure 13 reports tokens and wall-clock per run. The weakest functioning model, llama3.2-1b,
hits the step limit in 42% of runs and consumes the most tokens: failure is not cheap, so cost per success
varies more than cost per run. Wall-clock was measured with four parallel workers on one machine and is
indicative only.

Recommendations. (i) Treat tasks as the sampling unit and report task-bootstrap or hierarchical intervals
when R > 1 or T  50 (in our simulation grid the task bootstrap is mildly optimistic, and the hierarchical
interval relies on a beta model for task difficulty, Section 3.2); for very small single-run evaluations use an
exact binomial interval. (ii) Compare agents on the same tasks with paired task-level tests and correct for
multiplicity (Holm by default). (iii) Plan with the variance decomposition: prefer more tasks over more
repeats when the agent-by-task interaction is non-negligible, prefer repeats when the task pool is capped or
tasks are costly, and treat pilot-based task counts as orders of magnitude. (iv) Report passk with pass@k.
(v) If monitoring an evaluation as it runs, use a confidence sequence, not repeated fixed-sample tests, and
pre-declare an equivalence margin if equivalence is the goal. (vi) Publish per-task, per-run outcomes and the
number of attempts per submission, so that others can do this.

Parts of the hypothesis that were weakened or not supported. On local models the ranking is not
fragile: with gaps of tens of points all but 1 of 21 pairs are separable and the split-half rank correlation is
high, so the claim that rankings are unreliable is supported only for close systems (SWE-bench simulations
and re-analysis) and not for widely spaced ones. The fixed-budget tasks-versus-runs result was not tested on
real data, the real-data sequential analysis re-orders existing results rather than stopping a live run, and one
model (q2) never produced a parseable action, so its score measures protocol failure rather than capability.
Single hardware, single prompt protocol, small quantised models, no fault injection and raw trajectories not
retained: conclusions do not transfer to frontier agents. Three further corrections to the first version of this
study: the claim that no adjacent SWE-bench position is distinguishable holds only for the full set of entries
(Table 1); "more tasks beat more repeats" depends on the interaction and on whether the task pool is capped;
and the sign-flip test is exact only for symmetric differences, although it did not over-reject for skewed ones.

8 Limitations, Ethics and Broader Impact

Limitations. Inferential target. Tasks are treated as i.i.d. draws from the population defined by our
generator (or, for public data, from the benchmark), so intervals refer to that population and not to "ability";

                                                                     17
tasks within a benchmark are often related (same repository, same domain), which would make our task-level
intervals optimistic. Agents are fixed effects. Local models. The evaluation uses small quantised models, one
machine (an Apple laptop reported by the author; hardware is not verifiable from the stored results), one
prompt protocol, temperature 0.7 and no fault injection, so absolute scores and failure modes do not transfer
to frontier agents. Raw trajectories and caches are not retained; the stored aggregates cannot be re-derived
from raw runs. Benchmark. The environments are cleaner than real software tasks; checkers verify only the
state the generator anticipates; difficulty knobs are not calibrated to any human notion of difficulty. Statistics.
The variance decomposition is linear on the probability scale; the simulation model is one generator whose
robustness we explored only along the axes listed in Section 5; confidence sequences require i.i.d. tasks and
are conservative; plug-in power and tasks-needed figures are highly uncertain; Monte Carlo errors are 0.6­0.7
points. Public data. The SWE-bench files do not state coverage or attempts; we audit them but 17 entries
have no public logs. Scaffolds, budgets and dates are mixed. The  -bench data cover two models and two
domains.

Ethics and impact. No human subjects or personal data are involved; environments are synthetic and
public data are used under their licenses ( -bench: MIT; the SWE-bench experiments repository declares no
license, so we store only derived aggregates and a download script). Better error bars can reduce overclaiming,
but rigour can also be used to dismiss real improvements; a non-significant result is not evidence of equivalence,
which is why equivalence requires a margin. All experiments used free, local, open-weight models and public
data; no paid API was used.

9 Conclusion

Agent leaderboards carry less information than their precision suggests, most of all for close systems. Treating
the task as the sampling unit, testing the procedures against ground truth including where they fail, and
auditing what public data do and do not document give a more defensible reading of agent results. We release
the library, the benchmark, the scripts and the stored results so that every table, figure and number can be
regenerated from the stored aggregates in results/; the simulations and the public-data re-analyses can be
rerun from the scripts, whereas the local-model run cannot be repeated from the repository (Appendix G).

A Mathematical details

For balanced data with M agents, T tasks and R runs, the expected mean squares of the crossed model are

              E[M Sm] = e2 + Rm2 t + T Rm2 ,                    E[M St] = e2 + Rm2 t + M Rt2,
              E[M Smt] = e2 + Rm2 t,                            E[M Se] = e2,

and the estimators solve these for the components, truncating negative values at zero (the raw values are

retained). With R = 1 the interaction and error are confounded; the library flags this. For one agent, the
one-way model gives ^t2 = (M Sb - M Sw)/R and ^e2 = M Sw, which equals the REML estimate for balanced
data (verified against statsmodels in the test suite).

Unbiasedness of passk.   If  C        Bin(n, p)  then  E  C  =  n  pk ,  so  C  /  n  is unbiased for pk; similarly

   n-C     n

                                         T

Optimal runs. Minimising (st + se/R)(ctask + Rcrun) over R > 0 gives R = sectask/(stcrun); the planner

B Tool-protocol defect observed in Ollama

With Ollama 0.40.8 (macOS, Apple silicon), the native /api/chat tool-calling interface returned an empty
message (no content, no tool calls) for qwen2.5:3b on a file-creation task when eight tools were declared,
although the raw generation obtained from the /api/generate endpoint with the model's own template
contained a well-formed <tool_call> block. The failure was deterministic across seeds and temperatures in
the author's tests; it disappeared with a single declared tool or without a system message. The logs of these
tests are not part of the repository and the observation was not re-run during the revision of this paper, so it
is reported as an unverified observation about one server version, not about the model. The experiments use
the uniform text protocol of Section 4 regardless.
