\section{AgentAudit-Bench}\label{sec:bench}
\paragraph{Environments.} Six simulated worlds, all offline and deterministic: a virtual \emph{file system}; an in-memory \emph{SQLite} database; a REST-style \emph{CRM} (customers and tickets); room \emph{bookings}; \emph{web forms} with validation and option codes; and a \emph{tabular data} world with a restricted calculator. Each exposes 4--7 tools; tool errors are returned as observations, so an agent can recover from them.

\paragraph{Tasks.} A procedural generator creates \Ntasks{} tasks (60 per family) from a seed. Each family has five templates (for example, ``move every \texttt{.txt} file into \texttt{/archive}'', ``upgrade every customer in a city''), and two knobs sweep a factorial grid: \emph{horizon} (1--4 required operations or, for forms, 1--3 forms) and \emph{distractors} (0--2: confusable files, decoy tables, same-surname customers, extra forms, extra rows). Free-text values are quoted in instructions to avoid punctuation ambiguity, a flaw found when auditing early traces. A balanced one-third \emph{core} subset (\Ncore{} tasks, 20 per family) is used for the local-model evaluation.

\paragraph{Verification.} Success is decided by the final world state or the submitted answer, never by the agent's text. Every task is audited automatically in the test suite: a reference \emph{oracle} must solve it, a do-nothing agent must not, and generation and resulting state must be deterministic in the seed. These checks establish that tasks are solvable and non-trivial, not that the checker accepts every valid alternative solution: only the state the generator anticipates is verified.

\paragraph{Controlled stochasticity.} The benchmark includes a fault injector that fails each tool call independently with probability $q$, drawn sequentially along the call sequence from a generator seeded by (task, run) and independent of the agent; a failed call leaves the world unchanged and returns a transient 503, and injections are logged. Because draws are indexed by call number, two agents face the same failure pattern only if they make calls in the same order, so the injector gives matched failure \emph{probability} and seeds, not identical failure events. The injector is implemented and tested but was not enabled in the experiments reported here.

\paragraph{Agents and reproducibility.} Agents implement a small interface. All local models use one \emph{uniform text tool protocol}: tools are listed as JSON in the system prompt, a call is any JSON object with \texttt{name} and \texttt{arguments}, one call per turn is executed, and generation stops after it. Using one protocol removes chat-template differences from the comparison; it also sidesteps a server-side tool-call defect we observed once (Appendix~\ref{app:ollama}). A record/replay cache keyed by agent configuration, message history, tools and seed makes an experiment replayable without the model, provided the cache is available; the cache and the raw trajectories of the local-model run are \emph{not} in the repository, so the local-model numbers can be recomputed from the stored aggregates but not from raw runs. The runner executes runs in run-major order, so any prefix of an interrupted evaluation is balanced, and resumes from checkpoints.
