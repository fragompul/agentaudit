\section{Mathematical details}\label{app:ems}
For balanced data with $M$ agents, $T$ tasks and $R$ runs, the expected mean squares of the crossed model are
\begin{align*}
E[MS_m]&=\sigma^2_e+R\sigma^2_{mt}+TR\sigma^2_m, & E[MS_t]&=\sigma^2_e+R\sigma^2_{mt}+MR\sigma^2_t,\\
E[MS_{mt}]&=\sigma^2_e+R\sigma^2_{mt}, & E[MS_e]&=\sigma^2_e,
\end{align*}
and the estimators solve these for the components, truncating negative values at zero (the raw values are retained). With $R=1$ the interaction and error are confounded; the library flags this. For one agent, the one-way model gives $\hat\sigma^2_t=(MS_b-MS_w)/R$ and $\hat\sigma^2_e=MS_w$, which equals the REML estimate for balanced data (verified against statsmodels in the test suite).

\paragraph{Unbiasedness of pass$^k$.} If $C\sim\mathrm{Bin}(n,p)$ then $E\binom{C}{k}=\binom{n}{k}p^k$, so $\binom{C}{k}/\binom{n}{k}$ is unbiased for $p^k$; similarly $E\binom{n-C}{k}=\binom{n}{k}(1-p)^k$.

\paragraph{Pooled design effect.} Writing $\bar Y=\frac1T\sum_t \hat p_t$ with $\hat p_t\mid p_t\sim\mathrm{Bin}(R,p_t)/R$, the law of total variance gives $\mathrm{Var}(\bar Y)=\tau^2/T+E[p_t(1-p_t)]/(TR)$ and $E[p_t(1-p_t)]=p(1-p)-\tau^2$.

\paragraph{Optimal runs.} Minimising $(s_t+s_e/R)(c_\text{task}+Rc_\text{run})$ over $R>0$ gives $R^\star=\sqrt{s_ec_\text{task}/(s_tc_\text{run})}$; the planner evaluates the two neighbouring integers.

\section{Tool-protocol defect observed in Ollama}\label{app:ollama}
With Ollama 0.40.8 (macOS, Apple silicon), the native \texttt{/api/chat} tool-calling interface returned an empty message (no content, no tool calls) for \texttt{qwen2.5:3b} on a file-creation task when eight tools were declared, although the raw generation obtained from the \texttt{/api/generate} endpoint with the model's own template contained a well-formed \texttt{<tool\_call>} block. The failure was deterministic across seeds and temperatures in the author's tests; it disappeared with a single declared tool or without a system message. The logs of these tests are not part of the repository and the observation was not re-run during the revision of this paper, so it is reported as an unverified observation about one server version, not about the model. The experiments use the uniform text protocol of Section~\ref{sec:bench} regardless.

\section{Reproducibility status}\label{app:repro}
Verification levels are reported separately (details and commands in \texttt{FINAL\_REPRODUCIBILITY\_REPORT.md}).
\begin{enumerate}
\item \textbf{Raw outcomes from recorded trajectories.} Possible for the two public datasets only: \texttt{scripts/fetch\_taubench.py}, \texttt{fetch\_swebench.py} and \texttt{fetch\_swebench\_meta.py} download the trajectories and result files, and the re-analyses (\texttt{reanalyze\_*.py}, \texttt{audit\_taubench.py}, \texttt{audit\_swebench.py}) recompute every statistic from them. The SWE-bench data correspond to \texttt{swe-bench/experiments} in a state consistent with commit \texttt{92c5a4f} (inferred, not recorded at download; see Section~\ref{sec:public}). \textbf{Not possible} for the local-model study: raw trajectories, per-run outcomes and the record/replay cache are not in the repository.
\item \textbf{Statistics from raw outcomes.} Done for $\tau$-bench and SWE-bench (above; independent recomputation by the audit scripts, stored \texttt{reanalysis\_*.json} not regenerated) and, in part, for the simulations, which are seeded scripts: the S0 components coverage, type-I error, design and ranking were rerun in the final audit and matched the stored first-version values bit for bit; the S0 sequential component (S4), E5 and the equivalence study were rerun after the sequential fix, so S4 and E5 no longer equal the first-version values (S4 was then rerun again and matched the current stored file bit for bit); E1, E2, E3 and E6 were not rerun in the audit (stored results only, produced once in the first revision). Not possible for the local-model study; the per-pair $p$-values stored in \texttt{results/real\_main.json} allowed only the pair-count sensitivity to the degenerate model.
\item \textbf{Aggregates from stored aggregates.} Every table, figure and number is regenerated by \texttt{scripts/make\_paper\_assets.py} from \texttt{results/*.json}; this checks typesetting and consistency, not the experiments.
\item \textbf{Independent repetition of the evaluation.} Not performed for the local models (no Ollama server was available in the audit environment and the per-run outcomes needed for a comparison are not stored; the original run took hours on the author's laptop). Model tags and quantisations are in \texttt{configs/models.json}, the protocol in Appendix~\ref{app:prompts}; temperature $0.7$, 256 generated tokens per turn, four workers and seed 0 are in \texttt{scripts/run\_real.py}, but hardware, software versions and the Ollama build were not archived beyond what the text states. Server-side nondeterminism means a repetition would not reproduce individual outcomes even with the same seed. What was and was not repeated in the audit is itemised in item~2 and in \texttt{FINAL\_REPRODUCIBILITY\_REPORT.md}: S0 coverage, type-I error, design and ranking, bit for bit against the first-version values; S4, E5 and the equivalence study, after the sequential correction (S4 also against the current file); E1, E2, E3 and E6 not repeated (stored results of the first revision); the public SWE-bench and $\tau$-bench re-analyses recomputed independently from the raw public files by the audit scripts (headline values matched; the stored \texttt{reanalysis\_*.json} files were not regenerated); the local-model study not reproducible, because its raw data are not in the repository.
\end{enumerate}
\textbf{Tests.} The test suite (\texttt{pytest}, no network) passes, including audit tests for the betting capital process, the variance components and the allocation rule; \texttt{ruff} (check and format) is clean on the final tree; \texttt{mypy --strict} could not be run locally (a numpy stub rejects the local Python~3.14 interpreter); the continuous-integration results, including the type-check job, are those reported on the pull request, not in this paper. Seeds are fixed in every script. Compute: simulations on a laptop CPU in minutes to tens of minutes; no cloud and no paid API. Code, benchmark generator and scripts: \url{https://github.com/fragompul/agentaudit}.
