\section{Introduction}
Public leaderboards for LLM agents, from SWE-bench \citep{jimenez2024swebench} to $\tau$-bench \citep{yao2024taubench} and the Holistic Agent Leaderboard \citep{kapoor2026hal}, rank systems by a single success rate, often obtained from one run per task. Claims of a ``new state of the art'' are made on differences of one or two points. Three sources of randomness are rarely separated: \emph{which tasks} were sampled, \emph{which run} of a stochastic agent was recorded, and \emph{how} the agent and the task interact. The principle that evaluations need error bars is established \citep{miller2024error,bowyer2025clt,madaan2024variance,bouthillier2021variance}. What is less settled for agents is (i) which task-level procedures stay valid when every task is attempted several times, (ii) how a fixed budget should be split between more tasks and more repeats, and (iii) how much of an existing leaderboard survives a statistically careful reading.

\paragraph{Terminology.} A \emph{task} is one problem instance; a \emph{run} is one attempt of one agent on one task (the word \emph{attempt} is not used in any other sense); $R$ is the number of runs per task and $T$ the number of tasks. The \emph{benchmark score} of an agent is the mean over tasks of the per-task success rate. \emph{pass@$k$} is the probability that at least one of $k$ runs of a task succeeds, \emph{pass$^k$} the probability that all $k$ succeed; both are averaged over tasks.

\paragraph{Research questions.}
\begin{description}
\item[RQ1] When runs are clustered within tasks, which interval and test procedures keep their nominal coverage and error rate, and how badly do procedures that pool runs fail?
\item[RQ2] At a fixed budget of runs, is it better to spend it on more tasks or on more repeats, and what does the answer depend on?
\item[RQ3] How many differences between agents on public leaderboards (SWE-bench Verified, $\tau$-bench) are statistically distinguishable, and how sensitive is that count to what the public data do and do not document?
\item[RQ4] Does anytime-valid sequential comparison control false positives under continuous monitoring, and what does it cost in power?
\item[RQ5] On a controlled benchmark with several runs per task, how large is run noise relative to the score, and how reliable is the ranking of the evaluated agents?
\end{description}
Our working hypothesis was that many leaderboard differences are not distinguishable and that pass@$k$ hides unreliability that pass$^k$ reveals. We report where the evidence supports it and where it does not.

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{\textsc{AgentAudit}}, a typed Python library with a CLI and a browser playground. Estimators are implemented from scratch and cross-checked against SciPy and statsmodels in the test suite (Section~\ref{sec:method}).
\item \textbf{\textsc{AgentAudit-Bench}}: six offline deterministic environments and 360 generated tasks with horizon and distractor knobs, verified by final state, with a seeded tool-failure injector and record/replay caching (Section~\ref{sec:bench}).
\item \textbf{Pre-specified simulation studies} against exact ground truth for RQ1, RQ2 and RQ4, including robustness checks (prevalence, task heterogeneity, skewed paired differences, margin choice, near-tied leaderboards) that were written down before they were run (\texttt{docs/experiments.md}).
\item \textbf{A sensitivity analysis of public re-analyses}: SWE-bench Verified with its evaluation coverage and attempts audited, and $\tau$-bench with task-level inference (RQ3).
\item \textbf{A local-model case study} and the closed-form allocation rule of Section~\ref{sec:power} (RQ5).
\end{enumerate}

\paragraph{Findings in brief.} (1) Pooling runs is not merely loose: with ten runs per task, a nominal 95\% pooled Wilson interval covers \covWilsonTenRuns{} (\covrobWilsonMin{}--\covrobWilsonMax{} when tasks are very heterogeneous), while task-level intervals stay within \covrobBootMin{}--\covrobBootMax{} (task bootstrap) and \covrobBBMin{}--\covrobBBMax{} (beta-binomial) for $T\ge 50$; with $T=20$ and one run per task at extreme prevalence the task bootstrap falls to \covrobBootSmallMin{}--\covrobBootSmallMax{}. (2) Run-level tests reject a true null in \typeIPoolMc{} of simulations when the interaction is large; task-level tests stay below nominal. (3) At a fixed budget, tasks beat repeats only when agent-by-task interaction is non-negligible: the standard-error ratio of ten runs versus one is \allocRatioLow{} for small and \allocRatioHigh{} for large interaction.
